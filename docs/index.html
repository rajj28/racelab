Two agents checked the budget. Both said yes.

When AI agents share a budget, each one reads the balance, thinks, then spends. If two of them read before either writes, both see room and both approve. The money is gone twice and the database reports no error at all.

What actually happened

One account. A hard budget of $100. Twenty agents, each wanting to approve about $45. Here is a real run:

1

An agent reads the account. Nothing spent yet. Plenty of room, so it approves $45. This is correct.

$0
2

At the same moment two more agents read the account. They also see nothing spent, because nobody has finished writing yet. Both approve $45 too. Also correct, given what they saw.

$0
3

All three writes land. The account is now $35 over budget — and every agent reasoned correctly, so nothing anywhere reported a problem.

$135

Why doesn't the database just block this? The rule is "everything added together must stay under the limit." That is a statement about many rows at once, so it cannot be written as a check on any single row. The database is doing exactly what it was asked. Nobody asked it this question.

Then it gets harder

Part-way through the run, someone lowers the approval cap from $80 to $60. That is a policy change. It lives in the agent's notes — the text it looks up before deciding — and nowhere in the database.

So there are now two different rules that can break, and they break for completely different reasons:

Rule 1 · in the database Stay under $100

An agent that re-reads the balance can catch this, because the balance is a real number it can look up again.

Rule 2 · only in memory Stay under $60

Re-reading the balance tells you nothing about this. The cap changed in the notes, not in the data. You have to go back and re-read the notes.

Four ways to handle it

All four run the identical workload. They differ only in what they do when the database says "someone changed this underneath you." Pick one to see inside it.
